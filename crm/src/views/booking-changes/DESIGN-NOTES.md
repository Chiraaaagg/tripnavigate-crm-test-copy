# Booking changes screens — design notes (Accounts phase 3, track U, screen 15.10)

Built 13 November 2026 against preview data only (tracks G and H had no module yet). Synthetic content in every query and fixture.

## 21st.dev calls (search tool of the connected 21st.dev server; 1–3 word queries; no code retrieved)

## Adaptations

- One primary action per surface: "Request a change" on the Deal card, "Approve" per request on Approvals, "Record the supplier's answer" on the task, "Send change" in change mode.
- When all three request buttons are unavailable for the same reason, one shared reason line (`BlockedGroup`) instead of three identical lines.
- Fences: the Deal card never shows costs or rates; Sales see the customer charge only; the History table shows cost and change fee only when the DTO carries them (Manager, Accounts); a Purchase reader's history drops selling fields again in the view.
- Checked: 56 preview states at 1280 px and 375 px (no page-level sideways scroll, axe WCAG 2.1 AA clean, no console errors, no heading skips), keyboard path into the record dialog with the live budget hint.
- Dev-server note: a brand-new arbitrary Tailwind class (`sm:grid-cols-[10rem_1fr]`) was not generated by the running dev server; switched to an existing class.
