### Local render worker (12 October 2026; local stack only, rendering location PENDING)

`crm/scripts/render-worker.mjs [--once | --loop] [--worker name]` refuses to start unless `APP_ENV=local` (with a loopback Supabase URL), or `WORKER_ALLOW=1` together with `WORKER_PROJECT_REF` equal to the URL's project ref (review E6-2), and `SUPABASE_SECRET_KEY` is set. A FINAL job whose computed input differs from the requested one fails `input_invalid` without a PDF (E6-3); the layout check runs with JavaScript, the PDF is printed from a JavaScript-off context (E6-4). Per job (`render/worker-core.ts`, side effects injected; real ones in `server/render-worker-deps.ts` over Terra's service-role wrappers): claim → render input (conflict / input_changed stop) → the request's own view and adapter (input hash compared; a difference is a local note) → branded HTML → page checks → PDF (`render/pdf.ts`: Chromium, offline, every request except data: aborted) → layout codes → upload to `rendered-documents` at the claim's `objectPath` → complete with QA codes. A final document with placeholders, unsafe words or layout issues is never uploaded. Output is one JSON line per job (ids, codes, sizes, timings). `--sample view.json --out file.pdf` renders one view without a database (measurements).
